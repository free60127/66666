## 本轮发现与修复

| 优先级 | 问题与影响 | 修复 |
|---|---|---|
| P1 | Key 解析漏了 await，展开 Promise 后丢失 Key；普通用户及个人 Key 请求都报未配置 | 等待解析，并依据请求是否提供个人 Key 判断额度来源 |
| P1 | 学生端 AI 请求没有 Authorization，登录用户仍消耗访客 IP 的两次额度 | 批改、素材、识别、自测请求统一携带当前会话 |
| P1 | 先增加全网计数，再拒绝个人超额；重复点击能耗尽其他人的全网预算 | Redis Lua 同时检查个人和全局池，全部允许才增加；拒绝不增加任何池 |
| P1 | 配额 KV 故障标记被忽略，可能免费无限调用 | 故障拒绝并返回 503，Redis 请求增加 10 秒超时 |
| P1 | nginx 反代后未信任代理 IP，所有访客共用一个 IP 桶 | 线上 HOST=127.0.0.1、TRUST_PROXY_HOPS=1；8787 仅本机监听 |
| P1 | 发送注册验证码调用了要求密码的注册校验，导致发送接口直接拒绝 | 发码只校验邮箱；教师与学生验证码注册均验证通过 |
| P1 | 教师注册 UI 没有验证码字段，而后端已强制验证 | 增加发码、验证码输入、重发倒计时 |
| P1 | OCR 自定义视觉地址可能继承站点 Key，将密钥发送给用户指定地址 | 自定义地址必须提供用户自己的 Key；教师 Key 继续固定发往 DeepSeek |
| P2 | 队列已满或图片格式本地不合法仍消耗每日次数 | 请求接纳前预留队列容量、验证图片；繁忙/无效请求拒绝且不扣额度 |
| P2 | 个人视觉 Key 仍会受班级/免费主模型池限制 | 识别请求按实际视觉 Key 来源判断豁免 |
| P2 | 验证码错误尝试在限流前执行，发码邮箱限流故障被忽略 | IP/邮箱验证尝试限额、发码全局限额、故障拒绝 |
| P2 | 素材调试日志记录 Key 前缀 | 删除该日志 |
| P2 | 新额度测试未加入 npm test；验证码测试位于 process.exit 后，永远没有执行 | 纳入主测试、调整退出位置、补充模型路由/并发/安全测试 |
| P2 | 部分旧测试继承真实存储配置或被每日限额干扰 | 主测试统一使用临时存储、模拟 SMTP 和测试额度；浏览器探针隔离并清理数据 |
| P2 | 备案链接只在侧栏，手机收起侧栏后不可见，教师入口也没有 | 统一放到学生页和教师页底部，手机无需展开菜单即可查看 |

学生端和教师端新增了每日次数说明，明确批改、识别、素材、自测共用次数及北京时间零点重置。
已接纳并开始调用模型的任务失败仍计数；取消等待不会取消服务端已开始的任务。

## 教师统一 Key 专项

使用隔离的假模型记录实际 Authorization 和模型名，未发送真实 Key、未消耗生产 AI 费用。

- 成员的批改、素材、自测使用教师 Key。
- 班级每日额度独立于站点免费池；跨任务类型共用班级额度。
- 个人 Key 优先；个人视觉 Key 不被已耗尽的班级额度拦截。
- 成员伪造、清除 Key、归档班级后均不能使用该教师 Key。
- 学生 dashboard 只返回是否配置，不返回 Key。
- 客户端传入其他 Base URL 无法带走教师 Key或站点 Key。

## 依赖安全扫描

初始 npm audit 为 9 项：2 critical、3 high、4 moderate。
更新 Vite 6.4.4、Vitest 4.1.11、Mammoth 1.13.0 及相关传递依赖后，剩余 3 moderate，high/critical 为 0。
剩余是 Mammoth 命令行依赖链 `mammoth → argparse → sprintf-js` 的同一格式化拒绝服务问题。
截至检查，sprintf-js 最新版本仍为 1.1.3，官方公告覆盖此版本；不能声称已经零漏洞。

当前应用的 Node 后端不安装这些 npm 依赖，浏览器 DOCX 入口只按需加载 mammoth.browser，不使用 argparse 命令行路径。
因此未发现当前产品可触发该剩余告警的路径；后续若增加 Node 端 DOCX/CLI 处理，应重新评估并隔离。
Vite/Vitest 告警主要涉及开发或测试服务，本次并未证明线上已被攻击。
[Vitest 公告](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)、[Tinypool 公告](https://github.com/advisories/GHSA-85c8-ppgw-ccpr)、[剩余 sprintf-js 公告](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)。

## 线上现状

- 访客 IP：2 次/日；账号：3 次/日；站点免费池：300 次/日；班级 Key：每班 300 次/日。
- 个人 Key 不占上述池，但仍受通用限流和任务并发保护。
- 上述限制以任务次数计，不能当作人民币支出上限；同一任务可能重试或修复模型回复。
- 通用提交限流仍为每 IP 每分钟 30 次；任务执行并发 4、排队 50。
- 数据仍在 Upstash，应用运行在阿里云服务器。
- HTTPS 证书到期：2027-01-07 15:09:17（北京时间），certbot.timer 已启用；自动续期是否成功需监控。
- 当前服务使用 root 运行；.env 权限 600，后端仅监听 127.0.0.1:8787。
- 检查时服务器可用内存约 1GB，系统盘使用约 23%；这只是当前负载快照。
- 本轮已有代码与配置回滚备份、账号迁移数据备份，权限 600，保存在服务器私有目录。
- 账号迁移备份不包含所有班级和批改任务，不能等同完整数据库备份；也未建立定时异地备份。
- 仍有 2 个旧账号待本人登录后自动解密迁移；后台没有其明文密码，不能代解密。

## 下一步建议（按优先级）

### 上线后立即安排

1. **完整备份和恢复演练**：覆盖账号、增量快照、班级、成员、作业、共享课文、评语和批改结果。每日加密备份到另一台机器/对象存储，保留至少 7 个日备份和 4 个周备份，先在隔离环境验证可恢复。服务器快照不能覆盖远程 Upstash 数据。
2. **故障与花费监控**：每 5 分钟检查轻量健康接口；记录 5xx、429 类型、任务失败率、延迟、队列、内存/磁盘、SMTP 失败、Upstash 用量和模型余额。避免反复轮询会查数据库的 status 接口。告警不能依赖用户反馈。
3. **核对公安备案和隐私说明**：ICP 与公安联网备案应分别核对当地办理要求。登记主体、网站内容和域名保持一致，公安备案完成后展示对应标识。公开隐私政策、联系方式、账号注销与班级成绩保留规则。[政务服务办理依据](https://banshi.beijing.gov.cn/pubtask/task/1/110106000000/6ed7995c-bbb1-406e-9f6e-cacf4460ef7b_app.html)
4. **核对实际数据区域**：应用在国内不等于数据在国内；确认 Upstash 数据区域及姓名、学号、成绩的处理链路。若涉及境外提供或未成年人，应按适用要求处理告知、同意及保护措施，必要时迁移国内存储。[个人信息保护法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)
5. **保护密钥与运行权限**：轮换曾暴露的密钥并核对部署公钥；将 bts 改为专用普通用户运行，明确目录权限，保留受限 SSH 管理入口。班级 Key 建议进一步做服务端加密存储，密钥材料与备份分离。

### 稳定试运行后安排

6. **显示今日剩余次数**：目前显示每日规则和超额提示，下一步做具体余额、重置时间与“当前使用个人/班级/免费 Key”的清晰指示；记录失败归因，避免用户不理解耗额。
7. **按学校网络验证限流**：同校 NAT 出口的登录学生仍共用每分钟 30 次 IP 限流，整班同时提交可能被误拦。建议登录用户增加账号级桶，同时保留 IP 总保护，并做整班实测后调整。
8. **教师预算与控制**：每班 300 次不是每名学生 300 次；建议教师可设更低班级预算、轮换 Key，并查看班级用量、禁用情况和审计记录。不要直接取消通用资源保护。
9. **邮件可靠性**：验证不同邮箱的投递、垃圾邮件归类、延迟和失败；公共注册扩大后评估专用事务邮件服务。保持发码限额，避免验证码重发互相覆盖的误解。
10. **拆分代码与部署门禁**：App 和 server/index 都超过 2000 行，逐步拆分账号、班级、模型路由、配额和请求接纳；每次发布必须过测试、lint、构建并保留可回滚版本。不要用测试数量代替覆盖关键业务路径。
11. **费用和续期日历**：设置服务器/域名到期前 30、7 天提醒；服务器按原购买截图为 2027-03-03 到期，域名准确到期日需在控制台核对；定期验证证书续期结果。监控免费数据库命令、存储和流量，提前决定付费还是迁移。[Upstash 当前额度](https://upstash.com/pricing/redis)
