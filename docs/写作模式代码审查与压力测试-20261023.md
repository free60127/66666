## 已确认问题

### 1. [P1] 不同班级写作作业共用身份，页面题目和实际批改题目可以不一致

位置：[WritingStudio/index.jsx:162](/D:/AI/66666-main/src/components/WritingStudio/index.jsx:162)、[writing.js:8](/D:/AI/66666-main/src/writing.js:8)、[useGeneration.js:319](/D:/AI/66666-main/src/hooks/useGeneration.js:319)。

复现：从班级面板开始作业 A，输入作文，再从班级面板开始题目、材料不同的作业 B。

实际结果：页面继续显示 A，正文也保留 A。提交时，生成链路把题目强制替换成当前作业 B，却保留 A 的材料和正文。本次拦截到的真实前端请求为：

```text
页面题目：Discuss online learning.
页面材料：Material A.
已选择的作业：Assignment B
提交题目：Describe public transport.
提交材料：Material A.
提交正文：仍包含 ASSIGNMENT A ONLY.
```

根因：所有班级作文均设置 `id: 'assigned'`，`writingTopicKey()` 因而始终返回 `writing:assigned`。`appliedAssignedRef` 据此跳过新任务；即使卸载重开，也会从同一草稿槽恢复上一份作文。历史对比和计时身份同样依赖此键，存在错误归组风险。

建议：将 `classId + hwId` 贯穿 App、Studio、草稿、历史和提交上下文；题目、材料、词数和作业身份从同一份任务快照读取。发现界面身份与活动作业不同，应阻止提交并恢复正确任务，不能只静默替换题目。旧 `writing:assigned` 草稿保留为待恢复旧稿，避免迁移时绑定给所有新作业。

验证：三个独立组件断言均失败，覆盖不同作业的身份、原地换题、卸载后串稿；完整浏览器班级面板流程及提交请求再次确认。截图：[切换 B 后仍显示 A](/D:/AI/66666-main/tmp/writing-audit-20261023/assignment-wrong-question.png)。

### 2. [P1] 两个标签页写不同题，会覆盖另一页已保存的草稿

位置：[WritingStudio/index.jsx:71](/D:/AI/66666-main/src/components/WritingStudio/index.jsx:71)、[WritingStudio/index.jsx:85](/D:/AI/66666-main/src/components/WritingStudio/index.jsx:85)。

复现：打开同一网站的两个标签页；标签页 A 写入新句并等待保存；标签页 B 从旧状态切换到另一题并输入文字。

实际结果：B 用启动时的旧 `draftsRef` 重写整个 `bt-writing-studio`。检查浏览器存储，A 的 `LATEST TAB A EDIT` 已被旧正文覆盖，保存过程没有报错。A 尚未关闭时，内存中可能仍可找回新句，但落盘内容已经回退。

建议：按用户和题目独立保存草稿，增加修订版本及脏状态；对同一题并发编辑保留冲突副本或提示选择。优先使用 IndexedDB 事务；若继续使用 localStorage，至少避免整库旧快照覆盖，监听 storage/BroadcastChannel，并防止未修改的旧页面在离开时回写旧稿。只增加防抖不能解决此问题。

验证：[多标签页复现日志](/D:/AI/66666-main/tmp/writing-audit-20261023/multi-tab-verified.log)。

### 3. [P2] 班级作业完成后仍锁题，无法正常回到写作题库

位置：[App.jsx:193](/D:/AI/66666-main/src/App.jsx:193)、[App.jsx:1807](/D:/AI/66666-main/src/App.jsx:1807)、[useGeneration.js:433](/D:/AI/66666-main/src/hooks/useGeneration.js:433)。

复现：完成班级作文批改，返回编辑，再切到自由模式并切回写作模式。

实际结果：`bts-active-homework` 已清除，但 `writingTask` React 状态仍保留，Studio 持续收到 `assignedTopic`，界面仍显示“题目已锁定”，没有“返回题库”。切换模式也不能解除，刷新后才能摆脱旧状态。普通选课和新建路径也只有 `clearActiveHomework()`，未同步清理此状态。

建议：统一活动作业状态的读写与通知，完成、退出任务、新建练习都同步清理内存与持久化状态，保留该题草稿并恢复题库入口。

验证：浏览器确认 `activeCleared=true`、`noBank=true`、`lockedAfterSwitch=true`。截图：[作业完成后仍锁定](/D:/AI/66666-main/tmp/writing-audit-20261023/assignment-still-locked.png)。

### 4. [P2] 教师设置的写作词数刷新后丢失

位置：[classroom.js:28](/D:/AI/66666-main/src/classroom.js:28)、[App.jsx:199](/D:/AI/66666-main/src/App.jsx:199)。

复现：开始教师指定 300 词、题干未重复写词数的作文，刷新页面。

实际结果：刷新前目标 300 词，刷新后变成当前难度的默认 180 词，后续批改请求也携带 180。`activateHomework()` 未保存 `targetWords`，App 恢复任务时又明确设置 `words: null`，覆盖草稿原有词数。

建议：完整持久化并恢复 `targetWords`，旧记录缺字段时优先从相同作业的服务器详情或匹配草稿恢复；题干另有明确要求时仍以题干为准。

验证：[班级流程日志，含刷新前后文本及提交字段](/D:/AI/66666-main/tmp/writing-audit-20261023/class-ui.log)。

### 5. [P2] 批改 A 时转去写 B，A 的迟到结果会强制打断 B

位置：[App.jsx:186](/D:/AI/66666-main/src/App.jsx:186)、[WritingStudio/index.jsx:171](/D:/AI/66666-main/src/components/WritingStudio/index.jsx:171)、[useGeneration.js:429](/D:/AI/66666-main/src/hooks/useGeneration.js:429)。

复现：提交 A，延迟批改轮询返回；点击返回题库、选择 B 并开始输入；放行 A 的结果。

实际结果：自动跳到 A 的报告，顶部当前标题仍是 B。B 的文字已保存在草稿，没有观察到正文丢失，但用户正在写作时被强制导航。切写作题只更新题目和指导请求标识，没有作废父级批改自动导航标识。

建议：题目切换时更新练习会话标识。结果继续存入历史并提示已完成；仅当当前会话仍是提交时的会话、且用户未主动离开时才自动显示结果。流式首段和普通轮询结束两条路径都需覆盖。

验证：[旧结果覆盖新写作页面截图](/D:/AI/66666-main/tmp/writing-audit-20261023/late-result.png)；记录中 `resultTookOver=true`，`newDraftPreserved=true`。

### 6. [P3] 顶栏自定义作文标题没有随草稿保存

位置：[App.jsx:184](/D:/AI/66666-main/src/App.jsx:184)、[App.jsx:1611](/D:/AI/66666-main/src/App.jsx:1611)、[WritingStudio/index.jsx:84](/D:/AI/66666-main/src/components/WritingStudio/index.jsx:84)。

复现：修改顶栏标题，等待自动保存，刷新。

实际结果：自定义标题恢复为题库默认标题。标题仅位于 App 内存中，草稿快照中没有它；切回编辑时 `onTopicChange` 也会重设标题。

建议：将 `workTitle` 作为独立草稿字段保存与恢复，不直接修改题库 `zh`。提交和历史展示共用此字段。

## 其他修改建议（不计入上述已确认缺陷）

1. 明确历史页的“返回编辑”与“修改本篇”区别。目前看 A 的旧报告后点返回编辑，实际回到当前 B 草稿。这个行为符合现有回退实现，但不适合看完旧报告立即改同篇；建议增加“基于本次作文继续修改”，先保留当前草稿，再恢复对应任务和正文。
2. 写作草稿和指导目前不在备份/云同步协议内。`App.jsx` 的导出及同步快照、`syncDelta.js` 的白名单均未包含它们。界面说明目前是本地保存，因此此处列为能力缺口；建议提供草稿导出恢复，扩展云同步时同时定义跨设备修订冲突策略。
3. 抽出小范围的 `writingDraftStore` 与活动作业上下文，统一身份、版本、题面、词数、标题和存储错误处理。无需为了审查结果重写整个 App；先把最易冲突的状态集中管理。
4. 将本次反例转成正式回归测试：两个班级使用相同题干但不同作业 ID、A/B 切换、跨标签页不同题及同题冲突、完成任务后的解锁、刷新词数、批改迟到时不抢页面。当前既有全套测试全绿，仍不能覆盖这些组合场景。
5. 后续真实模型验收应另测偏题、材料摘要遗漏、图表数据错误、极短文、混合中英文、模型部分输出及评分分项一致性。程序层本次测试不能替代教学质量评估。

修复顺序建议：问题 1、2 → 问题 3、4、5 → 问题 6；前两项修好并补回归测试后，再继续扩展写作功能。
