# 双向批改修复与回归结果

日期：2026-10-11。基线：`993e966`。修复前问题见[提交核对与汉译英评估](./双向批改提交核对与汉译英评估-20261011.md)。

## 1. 本次落实的产品原则

- **AI 提升译文**提供更成熟的词汇、搭配和句式，匹配用户选择的学习等级。高级表达须保持原文的事实、范围、逻辑、程度和语气，不能以新增内容制造文采。
- **完整纠错版**修复学生的真实错误，并保留已经正确的措辞。涉及否定、必要条件、情态、倒装和补译时，给出完整句群，避免半截箭头替换后仍有错误。没有真实错误的句子，纠错版保留原句，AI 提升版独立保留。
- **评分**依据原文和学生实际译稿。简单句、常见准确词、合法并列/被动、没有习语，以及与 AI 或教材措辞不同，均不构成扣分理由。学习点和可选提升不扣分。

真实模型复测示例，学生原稿：

> He is very busy with work, but he still takes some time to read every day. Keeping this habit has helped him learn a lot.

AI 提升版：

> Busy as he is with work, he still sets aside time to read every day. Persisting in this habit has enabled him to learn a great deal.

这份原稿获得 **100 分**。两条表达升级均标为 `study`，没有扣分；完整纠错版保留学生原句。学习材料解释了让步倒装、`set aside time` 和 `persist in` 等表达。

## 2. 业务代码修复

| 先后、伴随、关联被升级为因果 | 明确区分关系类型；检查 `Thanks to`、`proved`、`caused`、`only if`、`may/will` 等语境 |
| 语法讲解错误 | 修正 after 的介词/连词边界、调查作主语、多个谓语的合法连接、不同层级连词及持续状态等规则 |

| 分数与账本或严重性不一致 | 校验五项权重、引用、严重性范围、错误覆盖与求和；维度扣分超出预算时记零，不跨维度再扣 |
| 流式先显示未经复核的分数 | 两个方向均在生成期间隐藏暂定评分，等待最终校验结果 |
| 模型改写用户输入 | 保存实际提交的原文、初稿和参考译文，覆盖模型回显的错误内容 |
| 复核失败时出现猜测分数 | 最多一次语义复核和一次评分补救；仍无有效账本时保留分析、标注评分暂不可用，不制造数字 |

## 3. 权重与兼容性

英译汉保留：理解准确 **40**、表达地道 **15**、语体得当 **10**、流畅度 **10**、完整性 **25**。

新结果评分版本分别为 `cn2en-evidence-v1` 和 `en2cn-evidence-v4`。历史结果保留原样；已有的同课进步比较会核对评分版本，避免把权重变化当作学习进步。关键反转或严重结构错误会在网页和 PDF 提示优先修正，总分不作为考试及格认定。

## 5. 实际限制与后续建议

1. **模型语义判断仍会波动。** 服务端能核验引用、算术、严重性对应范围和重复计费，不能自动证明模型对每一条“是否误译、属于哪一级”的判断都正确。实测也仍有合并讲解独立根因、严重性分类不稳定等现象。下一步应使用教师人工判定的固定样本校准，持续统计误判和漏检，而非按期望总分调高或调低。
2. **复核有时间与 token 成本。** 汉译英成功任务通常增加一次模型复核，必要时再补一次账本；调用次数有上限。免费额度仍按已受理的任务计数，但模型平台的实际成本需要观察。样本耗时约 15–25 秒，不是对长文或繁忙时段的保证。
3. **已有成绩不会自动重算。** 本次变更用于新生成任务；同一篇旧稿如需使用新规则，需重新批改。
4. **推送与服务器发布分别验证。** 首次推送本次修复时，阿里云尚未接入自动部署。随后已在 CI 增加阿里云发布：`main` 的静态检查、完整测试、账号测试和构建通过后，上传对应成品并检查服务，启动或内部健康检查失败则回滚代码。实际版本可查 `https://huiyiben.cn/release.json`，配置和运维说明见 `deploy/README.md`。旧结果不会因发布自动重算。
