# 英译汉语言学报告核对与改进

日期：2026-10-10。依据：用户提供的英汉对比、信息结构与句法重构报告；当前服务端代码；实际配置的 deepseek-chat 模型通过 HTTP 任务链路返回的结果。报告中的理论作为批改准则使用，不据此宣称已完成教学效果的实证验证。

## 1. 核对结论

此前版本已具备英译汉独立评分维度、原文与译稿的扣分引用、否定/条件/数字检查，以及一次独立语义复核。主要缺口是结构与篇章检查不够明确，而且正确中文异译仍可能被当成错误。

| 报告关注点 | 本次落实 |
| --- | --- |
| 主句、从句层级、修饰对象 | 先辨认施事、动作、对象和修饰关系，再检查中文重组；不以英文语序或句数为标准 |
| 名词化、无生命主语、被动 | 允许动词化、话题化、主动或无主句；也认可自然的名词结构、“报告强调”和被字句，不强制转换 |
| 形合与意合 | 可省略冗余连接词，但不得改变必要条件、让步、否定和因果强度 |
| 时间与因果 | 区分 after 与 because；上下文未给原因时，不凭常识把先后升级为因果；检查完成状态与事件顺序 |
| 信息焦点 | 保留 only、not until 等实质限制；普通强调结构或信息顺序的合理改写不自动扣分 |
| 情态与证据强度 | 区分可能、禁止、无义务、建议、预测与证明；目的不得译成已经实现的结果 |
| 歧义 | 上下文不能消歧时认可合理读法，用学习说明提示其他解释，不以“未保留所有解释”为由扣分 |
| 篇章指代与标点 | 检查 this 等是否指前文事件或命题；中文可换标点，但须保留解释、转折、插说等功能 |
| 语体与教学反馈 | 按原文语体判断，不强制短句、成语或文学化；建议聚焦本稿问题，复杂句点拨解释具体关系 |

以上规则集中在 `server/en2cnPrinciples.mjs`，分析、语义复核、评分补救共享，减少三处规则漂移。结构、时序、证据强度和跨句照应材料，即使第一轮没有报错，也可触发一次复核。简单低风险句仍可跳过复核。

## 2. 报告不宜机械照搬的地方

- “英语树状、汉语竹状”是倾向，不是句式评分模板；句末重量、句末焦点、已知/新信息与话题/述题不是一回事。
- 报告个别示例加入“然而”“许多”等信息，不能自动视为标准答案。拆句不能平白增加转折或数量。
- 将 has made 改成“随着”时，仍须保留致使关系；不能只留下同时发生。
- 被动改主动必须有施事依据，不能编出“有关部门”等主体。
- unintended 侧重非本意、非预期，不保证完全未被预见；不能把意图与预料混同。

## 3. 真实模型对照

测试使用自编材料，不改动真实班级、学生成绩或生产数据。候选应用在服务器独立端口、独立文件存储中运行，实际调用配置的模型，走正常提交、轮询、语义复核、账本验证及保存流程。

### 修改前确认的问题

1. 原文只说“可行性受到质疑后方案被否决”，下一句明确记录未给出原因。原系统仍认可“由于质疑而否决”，只报另一处时间反转，得94分。
2. 孤立的 `All students did not pass.` 缺少消歧上下文，原系统将“学生全都没通过”硬判错译，得96分。

### 修改及复测后的结果

样例见 `test/fixtures/en2cn-structure-cases.json`。下表取最终候选的最近结果；长句和时间组另复测了完整 AI 对照校正协议。

| 材料 | 故意错误/判断点 | 有错稿结果 | 正确或合理异译对照 |
| --- | --- | --- | --- |
| 委员会决定 | 宣布者与担忧者互换、定语错挂 | 2条必改，90分 | 0条必改，100分；认可拆句、名词转动词 |
| 方案审核 | 先后强加因果、批准与公布顺序反转 | 2条必改，88分；AI对照恢复先后关系 | 0条必改，100分；认可“未获通过”“报告强调” |
| 实验与限制 | only after 时间限制反转、this错指汽车、审查误作取消 | 3条必改，81分 | 0条必改，100分；认可跨句重组和标点调整 |
| 初步研究 | 初步性、证据/可能性、目的、条件、意图、证明与建议方向 | 6条必改，64分；覆盖7类预设错点，关联错点合并讲解 | 0条必改，100分；认可动词化、冒号和谨慎语气 |
| 歧义与法律语体 | 无消歧语境的否定范围、合理法律搭配 | 0条必改，100分；说明另一读法 | 0条必改，100分 |

四组有错稿的13条必改反馈覆盖14类预设错点；这不是系统整体准确率。五组对照稿均未被扣分，但部分仍收到可选润色或学习建议。

迭代中曾出现两种额外问题：模型把“AI译文错误、学生原译正确”的说明挂在学生 error 上；或只纠正 finding 而保留错误 AI 段落。本次明确分开两者的归属，复核独立返回经核对的整篇及逐句 AI 对照。错误例句、习语支持显式清除；这些更新进行字段、长度、句子编号和类型验证后原子应用，兼容旧复核格式。

一次中间长句结果的扣分账本不一致，评分补救仍未通过，系统保留批改但不显示伪造分数；后续复测为有效90分。模型仍有输出波动，不宣称该保护分支从此不会出现。

## 4. 工程验证

- `npm test`：服务端、账号、班级、同步等回归通过；22个 UI 测试文件、197项测试通过。
- 新增复核测试：结构风险路由、中文译法和句式点拨同步校正、错误学习材料清除、学生误判撤销后的扣分恢复、非法字段/重复编号拒绝、原对象不被修改。
- HTTP任务测试确认校正后的 AI 整篇、逐句译文和学习点保存到最终结果。
- `npm run lint`、`npm run build`、`git diff --check` 通过。构建仍有既存的 PDF 库大分块提示。
- 6份实际模型结果分别在1360×900电脑视口和360×800安卓尺寸触摸视口展示：12次页面检查通过，无脚本异常、无根页面横向溢出，修正后的 AI 译文和歧义说明可见。这是浏览器尺寸模拟，不是真机输入法测试。
- 全量测试首次遇到固定模拟端口9891无法绑定；改为系统分配模拟端口后通过，未改变生产服务配置。

## 5. 边界与后续

本次为批改政策与复核处理改进，不能代替教师评分。语义判断仍依赖模型，分数没有经教师盲评校准，可选建议仍有噪音。下一步应由教师对不同语体、长度和歧义语境进行盲评，统计漏判、误判和扣分一致性，而非继续单纯增加提示词长度。

新规则用于后续生成；旧历史批改保留原结果，不自动重新打分。
